# Changelog

## 2026-10-23
- T-001: scaffolded `uv`-managed Python 3.12 project (`pyproject.toml`, `uv.lock`, `.python-version`), source + test + migrations directory skeleton, placeholder `README.md`, and empty `.env.example`.
- T-002: added `justfile` recipe surface (install, dev, lint, format, typecheck, test, ci, migrate, seed, db-reset, install-hooks) and `.github/workflows/ci.yml` single-matrix-row pipeline running `just ci` with coverage artefact upload.
- T-003: wired pre-commit stack (`.pre-commit-config.yaml`), tool configs in `pyproject.toml` (`ruff`, `mypy --strict`, `pytest` + 90% coverage gate, `sqlfluff`, `djlint`, `bandit`), `detect-secrets` baseline, smoke test, and tolerant djlint call in `just lint` for the empty templates dir in Phase 0.
- T-004: typed, immutable `pydantic-settings`-driven `budget_planner.config.Settings` with `get_settings()` singleton (frozen, `extra="forbid"`, `BUDGET_` env prefix, loopback-only bind validator, ISO 4217 currency validator, `zoneinfo` validator); minimal FastAPI app in `budget_planner.web.app` exposing `/` and `/healthz` so `just dev` lands on an empty page; env contract documented in `.env.example`; `tests/unit/test_config.py` covers defaults, overrides, validation errors; `httpx2` added as dev dep for Starlette 1.9 TestClient. Pre-commit revs bumped to match installed `ruff` 0.17 and `mypy` 2.4.
- T-010: hand-rolled SQL migration framework. `budget_planner.db.connection.get_connection` opens SQLite with `foreign_keys = ON`, WAL journal, `row_factory = Row`, `isolation_level = None`. `budget_planner.db.migrate` discovers numbered `NNNN_slug.sql` files, verifies monotonic unique versions, enforces sha256 checksum on already-applied migrations, splits each file into statements (respecting `--` comments and single/double-quoted strings), and runs each inside an explicit BEGIN/COMMIT with rollback-on-failure. `migrations/0001_schema_meta.sql` seeds the `schema_migrations` ledger. `just migrate` wires `python -m budget_planner.db.migrate`. Unit tests under `tests/unit/db/` cover connection pragmas, discovery edge cases, idempotency, checksum drift, transactional rollback, and the SQL splitter.
- T-012: `migrations/0003_seed_system_rows.sql` idempotently seeds `users(id=1, name='default')` and the two system categories `Transit` (direction=`transit`) and `Reconciliation` (direction=`adjustment`), both flagged `is_system=1`. Seed inserts bypass `audit_log` by design (schema fact, not user action). `budget_planner.domain.system_categories` exports `TRANSIT_CATEGORY_NAME`, `RECONCILIATION_CATEGORY_NAME`, and `SYSTEM_CATEGORY_NAMES`. `budget_planner.db.seed` provides a thin CLI shim re-using `apply_migrations` so `just seed` works. `tests/unit/db/test_seed_data.py` verifies seed rows, idempotency, empty `audit_log`, and the constants module.
- T-011: `migrations/0002_core_schema.sql` creates the 13 core tables (`users`, `accounts`, `categories`, `transactions`, `planned_transactions`, `recurring_rules`, `recurring_rule_overrides`, `budget_defaults`, `budget_recurring_overrides`, `budget_one_off_overrides`, `account_snapshots`, `fx_rates`, `audit_log`) with CHECK constraints (direction, cadence, operation, amount <> 0, length(currency)=3, month/year ranges, end_date >= start_date), FKs (deferred where circular), indexes incl. partial `WHERE deleted_at IS NULL` uniques on `(user_id, name)`, `(category_id)`, `(category_id, month)`, `(category_id, year, month)`, and uniqueness on `(date, from_ccy, to_ccy)` for `fx_rates`. `categories.is_system` column added for the Phase 2 service-layer protection of system categories. sqlfluff config excludes `RF04` (keyword-as-identifier) because `fx_rates.date` is a legitimate column name per plan. `tests/unit/db/test_core_schema.py` asserts table presence, index presence, FK enforcement, every CHECK constraint, partial-unique soft-delete round-trip, and the `(date, from_ccy, to_ccy)` fx uniqueness.
