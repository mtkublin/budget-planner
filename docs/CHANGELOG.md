# Changelog

## 2026-10-23
- T-022: recurring occurrence generator at `src/budget_planner/services/recurring.py`. Pure, DB-free; `generate_occurrences(rule, range_start, range_end)` expands monthly / quarterly / yearly cadences via `dateutil.relativedelta(day=anchor_day)` to pick up free end-of-month clamping (Jan 31 → Feb 28 / 29, Feb 29 yearly → Feb 28 in non-leap years recovering to Feb 29 next leap), honours `month_of_year` on yearly rules (rolls to next year when the first candidate falls before `start_date`), and short-circuits inactive rules. `apply_overrides(occurrences, overrides)` runs the (`skipped` | `overridden`) state machine keyed on the ORIGINAL `occurrence_date`: `skipped` drops the match, `overridden` replaces nullable fields (`amount_override`, `description_override`, `date_override`) leaving the canonical `occurrence_date` intact and setting `effective_date`; orphan overrides log DEBUG, duplicate keys log WARNING (last-wins by id). Output sorted by `(effective_date, occurrence_date)`. `expand(...)` composes both. 24 unit tests under `tests/unit/services/test_recurring.py` cover every cadence happy path, EOM clamp, leap-year Feb 29, year/quarter boundaries, lifecycle (`active`, `start_date`, `end_date`), override semantics, orphan + duplicate paths, partition invariant; 100% branch coverage.
- T-021: balance service at `src/budget_planner/services/balance.py`. `signed_legs(txn, direction)` is a pure DB-free helper producing one leg for income/expense/adjustment and two for transit per ADR-0008 + ADR-0009 (adjustment amount is pass-through signed, all others flip sign from positive-stored amount). `derive_balance(conn, account_id, as_of_date=None)` sums the legs touching `account_id` (either as source or `dest_account_id`) on top of `account.opening_balance`; `as_of_date` is inclusive, ignores soft-deleted rows, raises `AccountNotFoundError` on unknown id. `account_stats(...)` returns the Phase 1 `AccountStats` DTO extended with `avg_inflow_minor` / `avg_outflow_minor` (`ROUND_HALF_EVEN` means over income/expense legs only; transit + adjustment count towards `txn_count` + `last_txn_date` but not averages). `AccountStats.last_activity_date` property parses the ISO string for typed consumers. Reuses existing repositories (`accounts`, `categories.list_all`, `transactions.list_filtered` with `account_or_dest` + `up_to_date`) — no new repository functions added. 18 unit tests under `tests/unit/services/test_balance.py` covering each direction, as-of-date inclusivity, soft-delete exclusion, isolation, unknown-id error, mixed-stat averaging; 99% branch coverage.
- T-020: FX service at `src/budget_planner/services/fx.py`. `get_rate(conn, http, on_date, from_ccy, to_ccy) -> Decimal` short-circuits on identity, hits the local SQLite cache, else fetches `GET {fx_api_url}/{YYYY-MM-DD}?from=&to=` and persists; on `httpx.HTTPError` / non-200 / missing-key JSON / parse failure, logs a WARNING and falls back to the most recent cached rate on-or-before `on_date` (never persists stale rates under the requested date), else raises `FxUnavailableError`. `convert(...)` scales via `domain.money.currency_decimals` with `ROUND_HALF_EVEN`, preserves sign, and short-circuits identity. HTTP client is injected (never constructed in-service) per ADR-0021. `repositories.fx.latest_rate` gained a `on_or_before: date | None` kwarg for the fallback. 15 unit tests under `tests/unit/services/test_fx.py` using `httpx.MockTransport` (no `pytest_httpx` dependency added); 100% coverage on the service module.
- T-028: canonical audit helper landed at `src/budget_planner/services/audit.py`. Thin wrapper over the Phase 1 `repositories._shared.write_audit` that validates the `(operation, prev, new)` shape per ADR-0019 (`create`/`undelete` need `prev=None, new!=None`; `update` needs both; `delete` needs `prev!=None, new=None`). Raises `AuditShapeError` on violation (invalid op or wrong null-shape). Repositories keep calling `_shared.mutate(...)` (unchanged); the new module is the single canonical reference for direct audit writes. 8 new unit tests under `tests/unit/services/test_audit.py` + shared `conftest.py` fixture; coverage stays at 99%.

- T-010: hand-rolled SQL migration framework. `budget_planner.db.connection.get_connection` opens SQLite with `foreign_keys = ON`, WAL journal, `row_factory = Row`, `isolation_level = None`. `budget_planner.db.migrate` discovers numbered `NNNN_slug.sql` files, verifies monotonic unique versions, enforces sha256 checksum on already-applied migrations, splits each file into statements (respecting `--` comments and single/double-quoted strings), and runs each inside an explicit BEGIN/COMMIT with rollback-on-failure. `migrations/0001_schema_meta.sql` seeds the `schema_migrations` ledger. `just migrate` wires `python -m budget_planner.db.migrate`. Unit tests under `tests/unit/db/` cover connection pragmas, discovery edge cases, idempotency, checksum drift, transactional rollback, and the SQL splitter.
- T-013: repository layer. ADR-0022 (new) pins soft-delete + audit-in-same-transaction discipline. `budget_planner.repositories._shared` exposes a generic `mutate[T]` helper that runs the mutation inside an explicit `BEGIN`/`COMMIT` and writes a matching `audit_log` row in the same transaction, with `transaction()` context manager and `write_audit()` for direct use. One module per entity under `src/budget_planner/repositories/` (`accounts`, `categories`, `transactions`, `planned`, `recurring`, `budgets`, `snapshots`, `fx`, `audit`): pure functions only, hydrators parse ISO timestamps + `Decimal` FX rates. Readers default-filter `deleted_at IS NULL` and accept `include_deleted: bool = False`. Transactions / planned filter DTOs are compiled into parametrised WHERE clauses with `IN (...)` placeholders for id and direction sets. `transactions.list_filtered` joins `categories` so direction filtering stays in SQL. SQLite `detect_types` disabled to avoid Python 3.12's deprecated `convert_timestamp` emitting warnings under `filterwarnings=["error"]`. `ruff` per-file ignore for `S608` on `repositories/*.py` (dynamic SQL is columns-from-DTO, never user input). 92 new tests under `tests/unit/repositories/`: audit shape, soft-delete round-trip, filter matrix, rollback-on-failure, append-only snapshots/fx, override upsert. Coverage ends at 99% (branch gaps only on dual-path `include_deleted` branches in defensively safe hydrators).
- T-014: domain layer. Frozen `slots=True, kw_only=True` dataclasses per entity (`Account`, `Category`, `Transaction`, `PlannedTransaction`, `RecurringRule`, `RecurringOverride`, `Occurrence`, `BudgetDefault/RecurringOverride/OneOffOverride`, `AccountSnapshot`, `AccountStats`, `FxRate`, `AuditEntry`) plus matching `New*`/`Patch*` DTOs and `TransactionFilter`/`PlannedFilter` tuple-based filter DTOs. Enums (`Direction`, `Cadence`, `OverrideState`, `AuditOperation`) are `StrEnum` subclasses whose `.value` matches the SQL CHECK literals. `domain/money.py` adds `currency_decimals`, `to_minor_units`, `from_minor_units`, and `format_money`, with per-currency decimals (0 for JPY/KRW, 2 default). `Patch*` DTOs expose `as_dict()` returning only non-`None` fields via `dataclasses.fields()` (slots-safe). `tests/unit/domain/` covers enum literals, money conversion + rounding + round-trip + formatting, frozen-ness, DTO defaults, and hashability of filter DTOs. 100% coverage retained.
