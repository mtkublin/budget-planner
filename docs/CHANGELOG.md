# Changelog

## 2026-10-24
- T-025: deterministic forecast service at `src/budget_planner/services/forecast.py`. `forecast(conn, http, today, horizon_days, base_currency) -> ForecastSeries` projects per-account balances forward across `[today, today + horizon_days]` (length `horizon_days + 1`). Day 0 anchors on `services.balance.derive_balance(conn, a.id, as_of_date=today)` for every live account; subsequent days apply operation-date-bucketed `_CashEvent`s derived from `planned_repo.list_filtered(..., promoted=False)` unioned with virtual occurrences from `services.recurring.expand(...)`. De-dup keyed on `(recurring_rule_id, occurrence_date)` prefers persisted planned rows over the virtual expansion (same rule as T-023 `list_planned`). Signed-leg emission mirrors `services.balance.signed_legs` (income +, expense −, transit = two legs); adjustment-direction planned rows are skipped with a DEBUG log (T-023 blocks promotion so this is a defensive path). FX conversion fetches `ccy → base_currency` once per distinct account currency via `services.fx.get_rate(conn, http, today, ...)` and holds the rate constant across the horizon (ADR-0006 / ADR-0015 — forecast is not a currency forecast); conversion arithmetic is pure `Decimal` with `ROUND_HALF_EVEN` per-account rounding then integer sum. Frozen `AccountBalancePoint` / `DayPoint` / `ForecastSeries` dataclasses (slots, kw_only; ADR-0021). Pure w.r.t. DB snapshot + FX cache + injected `today` — determinism tested with twice-call equality. 23 unit tests cover: anchor equality with `derive_balance`, income/expense/transit event application, virtual recurring, persisted-overrides-virtual dedup, FX aggregation with stale-cache fallback via `httpx.MockTransport` that raises `ConnectError`, soft-deleted planned exclusion, deactivated rule, skipped-override removal, horizon=0 edge, horizon=60 length, flat-line for untouched account, event-sum-equals-delta property, empty-DB zero-filled series, rule-outside-window skip, adjustment-direction defensive skip, negative-horizon `ValueError`. 100% branch coverage on service module. Total coverage 99.31%.

## 2026-10-23
- T-026: reconciliation service at `src/budget_planner/services/reconciliation.py`. `reconcile(conn, account_id, actual_balance_minor, today, note=None)` computes `delta = actual - derived` via `services.balance.derive_balance`, inserts a signed adjustment-direction `transactions` row under the seeded `Reconciliation` category (`direction=adjustment`, ADR-0008 single-signing exception), returns the new `Transaction`. Guards: `AccountNotFoundError` (unknown id), `CannotReconcileDeletedAccountError` (soft-deleted account), `NoAdjustmentNeededError` (delta == 0; schema CHECK `amount <> 0` would also catch it), `MissingSystemCategoryError` (seeded `Reconciliation` row missing). Description `"auto-reconciliation {today}"` with optional ` — {note}` suffix. `today` is injected (routers compute in `Europe/Warsaw`). Audit row written through the repository's single-transaction mutate; rollback test patches `transactions_repo.create` to raise and asserts no partial state. 16 unit tests including parametrised post-condition round-trip over positive / negative / mid-range actuals, repeated-call idempotence (zero delta), negative balance accounts (credit-card style).
- T-023: planned log service at `src/budget_planner/services/planned.py`. `list_planned(conn, filters)` UNIONs persisted `planned_transactions` rows (via `planned.list_filtered`) with virtual recurring occurrences expanded by `services.recurring.expand` — dedup prefers the persisted row when `(recurring_rule_id, occurrence_date)` collide (ADR-0013). Non-date filters (`account_ids`, `category_ids`, `recurring_rule_id`, `promoted`) applied in-process; defaults to the current month window if the filter omits both bounds. Deterministic sort: `(operation_date, kind="virtual" last, persisted_id)`. `promote_to_actual(conn, planned_id, PromotionEdits)` validates (`AlreadyPromotedError`, `CannotPromoteDeletedError`, `UnsupportedDirectionError` for adjustment direction, cross-currency transit = `ValidationError`, zero amount = `ValidationError`), then atomically inserts the transaction with `promoted_from_planned_id` and stamps `planned.promoted_to_txn_id` under one DB transaction. `_shared.transaction()` was upgraded to **nest via SAVEPOINT** so services can compose two repository mutations without the SQLite "cannot start a transaction within a transaction" trap; outer BEGIN/COMMIT, inner `SAVEPOINT sp_N / RELEASE / ROLLBACK TO`. 21 unit tests cover UNION dedup, skipped + overridden virtuals, filter semantics, deactivated-rule hiding, promote happy path + edits + each error branch, rollback-on-stamp-failure (patches `stamp_promotion` to raise), and nested-savepoint rollback. 98% branch coverage on service module.
- T-027: generic export service at `src/budget_planner/services/export.py`. `ExportColumn(key, header, kind, currency_key=None)` describes one column; `kind ∈ {"int","money_minor","date","str","bool"}`. `export_csv(rows, columns) -> bytes` emits UTF-8 LF CSV via stdlib `csv.writer` (`excel` dialect) with header row from column headers; money is raw integer minor units (no float scaling), booleans render `"true"/"false"`, dates ISO, `None` → empty string. `export_parquet(rows, columns) -> bytes` builds a `pandas.DataFrame` with explicit nullable dtypes (`Int64Dtype`, `BooleanDtype`, `StringDtype`) + an explicit `pyarrow.Schema` (`int64`, `date32`, `bool`, `string`), writes zstd-compressed; preserves nulls. `UnknownColumnError` raised when a row lacks a declared column key. 15 unit tests cover empty rows, null handling, unicode, bool/date formatting, deterministic CSV bytes, Parquet round-trip + dtype assertions. 100% coverage on service module.
- T-024: budget service at `src/budget_planner/services/budget.py`. `resolve_budget(conn, category_id, year, month)` null-coalesces one-off → recurring → default (zero is a valid distinct value from `None`). `month_summary(conn, year, month)` returns a `MonthSummary` of `CategoryBudgetLine`s — one per live expense category — with `budgeted / spent / remaining`, `avg_monthly_overall` (distinct-active-month count), `avg_this_year` (YTD / month), `delta_vs_prev_month` (handles January → previous December). All averages use `Decimal` + `ROUND_HALF_EVEN`. Totals exclude unbudgeted lines. Service aggregates in Python over `transactions.list_filtered(directions=(EXPENSE,))` rather than extending the repository with aggregate SQL (keeps the repo thin per ADR-0022). `prev_year_month(y, m)` is exported for routers. 18 unit tests cover resolution tiers, zero vs null, January rollover, YTD + overall averaging, soft-delete + income + adjustment exclusions, totals, sort order; 100% coverage on the service module.
- T-022: recurring occurrence generator at `src/budget_planner/services/recurring.py`. Pure, DB-free; `generate_occurrences(rule, range_start, range_end)` expands monthly / quarterly / yearly cadences via `dateutil.relativedelta(day=anchor_day)` to pick up free end-of-month clamping (Jan 31 → Feb 28 / 29, Feb 29 yearly → Feb 28 in non-leap years recovering to Feb 29 next leap), honours `month_of_year` on yearly rules (rolls to next year when the first candidate falls before `start_date`), and short-circuits inactive rules. `apply_overrides(occurrences, overrides)` runs the (`skipped` | `overridden`) state machine keyed on the ORIGINAL `occurrence_date`: `skipped` drops the match, `overridden` replaces nullable fields (`amount_override`, `description_override`, `date_override`) leaving the canonical `occurrence_date` intact and setting `effective_date`; orphan overrides log DEBUG, duplicate keys log WARNING (last-wins by id). Output sorted by `(effective_date, occurrence_date)`. `expand(...)` composes both. 24 unit tests under `tests/unit/services/test_recurring.py` cover every cadence happy path, EOM clamp, leap-year Feb 29, year/quarter boundaries, lifecycle (`active`, `start_date`, `end_date`), override semantics, orphan + duplicate paths, partition invariant; 100% branch coverage.
- T-021: balance service at `src/budget_planner/services/balance.py`. `signed_legs(txn, direction)` is a pure DB-free helper producing one leg for income/expense/adjustment and two for transit per ADR-0008 + ADR-0009 (adjustment amount is pass-through signed, all others flip sign from positive-stored amount). `derive_balance(conn, account_id, as_of_date=None)` sums the legs touching `account_id` (either as source or `dest_account_id`) on top of `account.opening_balance`; `as_of_date` is inclusive, ignores soft-deleted rows, raises `AccountNotFoundError` on unknown id. `account_stats(...)` returns the Phase 1 `AccountStats` DTO extended with `avg_inflow_minor` / `avg_outflow_minor` (`ROUND_HALF_EVEN` means over income/expense legs only; transit + adjustment count towards `txn_count` + `last_txn_date` but not averages). `AccountStats.last_activity_date` property parses the ISO string for typed consumers. Reuses existing repositories (`accounts`, `categories.list_all`, `transactions.list_filtered` with `account_or_dest` + `up_to_date`) — no new repository functions added. 18 unit tests under `tests/unit/services/test_balance.py` covering each direction, as-of-date inclusivity, soft-delete exclusion, isolation, unknown-id error, mixed-stat averaging; 99% branch coverage.
- T-020: FX service at `src/budget_planner/services/fx.py`. `get_rate(conn, http, on_date, from_ccy, to_ccy) -> Decimal` short-circuits on identity, hits the local SQLite cache, else fetches `GET {fx_api_url}/{YYYY-MM-DD}?from=&to=` and persists; on `httpx.HTTPError` / non-200 / missing-key JSON / parse failure, logs a WARNING and falls back to the most recent cached rate on-or-before `on_date` (never persists stale rates under the requested date), else raises `FxUnavailableError`. `convert(...)` scales via `domain.money.currency_decimals` with `ROUND_HALF_EVEN`, preserves sign, and short-circuits identity. HTTP client is injected (never constructed in-service) per ADR-0021. `repositories.fx.latest_rate` gained a `on_or_before: date | None` kwarg for the fallback. 15 unit tests under `tests/unit/services/test_fx.py` using `httpx.MockTransport` (no `pytest_httpx` dependency added); 100% coverage on the service module.
